# สถานะระบบก่อนการ Build และติดตั้ง Kernel (Baseline)

ไฟล์นี้บันทึกสถานะของระบบ Ubuntu VM ก่อนที่จะทำการคอมไพล์และติดตั้ง kernel ตัวใหม่ เพื่อใช้เป็นข้อมูลอ้างอิงเปรียบเทียบกับสถานะหลังการติดตั้ง

## ข้อมูล Kernel ที่ใช้งานอยู่

ก่อนเริ่มกระบวนการ build ระบบใช้งาน kernel เวอร์ชันมาตรฐานของ Ubuntu คือ `7.0.0-31-generic` ตรวจสอบได้จากคำสั่ง `uname -a` ซึ่งแสดงผลลัพธ์เต็มว่า `Linux Ubuntu 7.0.0-31-generic #31-Ubuntu SMP PREEMPT_DYNAMIC Sat Aug 1 04:26:38 UTC 2026 x86_64 GNU/Linux` โดยระบุว่าเป็น build ลำดับที่ 31 ของ Canonical ที่ compile เมื่อวันที่ 1 สิงหาคม 2026 และคำสั่ง `uname -r` ยืนยันหมายเลขเวอร์ชันตรงกันคือ `7.0.0-31-generic`

## ไฟล์ Kernel ในโฟลเดอร์ /boot

เมื่อตรวจสอบโฟลเดอร์ `/boot` ด้วยคำสั่ง `ls -lh /boot` พบว่ามีไฟล์ของ kernel สองเวอร์ชันเก็บอยู่ ได้แก่เวอร์ชันปัจจุบัน `7.0.0-31-generic` และเวอร์ชันก่อนหน้า `7.0.0-30-generic` ซึ่งเป็นเรื่องปกติของ Ubuntu ที่มักเก็บ kernel เวอร์ชันเก่าไว้เผื่อต้อง rollback แต่ละเวอร์ชันประกอบด้วยไฟล์หลัก 4 ชนิด คือ `vmlinuz` (kernel image ขนาดประมาณ 17MB) `initrd.img` (initial ramdisk ขนาดประมาณ 41MB) `System.map` (ตารางสัญลักษณ์ของ kernel ขนาดประมาณ 11MB) และ `config` (ไฟล์ configuration ขนาดประมาณ 302KB) นอกจากนี้ยังพบ symbolic link ชื่อ `vmlinuz`, `initrd.img`, `vmlinuz.old`, `initrd.img.old` ที่ชี้ไปยังไฟล์จริงของแต่ละเวอร์ชัน เพื่อให้ boot loader อ้างอิงได้ง่าย

## พื้นที่ดิสก์และหน่วยความจำ

จากคำสั่ง `df -h` พบว่าพาร์ติชันหลัก `/dev/sda2` มีขนาดรวม 25GB ถูกใช้งานไปแล้ว 6.7GB คิดเป็น 29% เหลือพื้นที่ว่างอีก 17GB ซึ่งเพียงพอสำหรับกระบวนการ build kernel ที่ต้องใช้พื้นที่ชั่วคราวจำนวนมาก ส่วนคำสั่ง `free -h` แสดงว่าระบบมีหน่วยความจำ (RAM) ทั้งหมด 1.6GB ถูกใช้งานไปแล้ว 1.1GB เหลือพื้นที่ว่างจริง 131MB แต่มีหน่วยความจำที่พร้อมใช้งาน (available) อยู่ที่ 520MB เนื่องจากระบบเก็บ buffer/cache ไว้ 568MB ซึ่งสามารถคืนกลับมาใช้งานได้เมื่อจำเป็น ในขณะที่ swap space ยังไม่ได้เปิดใช้งาน (0B) ในช่วงเวลานี้

## สเปกฮาร์ดแวร์ของเครื่อง

ผลลัพธ์จากคำสั่ง `lscpu` แสดงว่า VM นี้รันบนสถาปัตยกรรม x86_64 ใช้ CPU จำลองจาก AMD Ryzen 5 220 พร้อมกราฟิก Radeon 740M จำนวน 4 core โดยไม่มีการแบ่ง thread ต่อ core (1 thread per core) ทำงานผ่านระบบ virtualization แบบ KVM ในโหมด full virtualization ซึ่งสเปกนี้ถือว่าเพียงพอสำหรับการ build kernel แม้จะไม่เร็วมากนักเมื่อเทียบกับเครื่องที่มี core จำนวนมากกว่า
